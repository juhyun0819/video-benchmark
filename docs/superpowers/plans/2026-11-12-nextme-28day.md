# NextMe 28-day Timeline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Generate one 28-day timeline manifest for the NextMe wearer, with home and work fixed to NextMe, by adding:
- late workdays;
- the first multi_day exception (a real NextMe trip);
- a bounded allowance for a missing required home_morning;
- a committed NextMe L3 labeler with manual-review overrides.

**Spec:** `docs/superpowers/specs/2026-11-12-nextme-28day-design.md` (approved). The base spec is `docs/superpowers/specs/2026-11-12-synthetic-timeline-generation-design.md` (rev3). Earlier rulings: `docs/superpowers/plans/2026-11-12-synthetic-timeline-rulings.md`.

**Tech:** Node 24, TS strict ESM, zod 3, vitest. No new deps.

## Decisions
- **N1. Late workdays:**
  - Dial: `dials.late_workdays_per_week` (int 0..5, default 0).
  - Weekday choice: weekdays are drawn once per person with `rngFor(seed, "late_weekdays")` (k distinct of Mon–Fri) and are fixed every week, with no routine perturbation.
  - Day type: `workday_late` with template `workday`. Day exceptions apply to `workday_late` as to `workday`, using the same catalog entries.
  - Donor: `donors.weekday_late` comes from the weekday pool filtered to `work_start ∈ [690, 900]`. It uses the same backoff, acceptance and required-slots check as the weekday donor. It is selected only when the dial > 0.
  - Realized: `realized.late_workday_count`.
- **N2. Trip nodes:**
  - Node kind: `trip` `{ lodging_setting, outing_setting, meal_setting }`. Virtual nodes are `<trip>:lodging|outing|meal`, and template nodes are written `$trip:lodging` etc.
  - Clip labels: clips use the fixed node labels `trip:lodging`, `trip:outing` and `trip:meal`.
  - Binding: gains `day_group_sequence?: string[]`.
  - Gap place kinds: lodging → home, outing → hobby, meal → frequent_place.
- **N3. Trip placement:**
  - Dial: `dials.trips: [{ node, length_days }]` (default []). Length must equal the binding's sequence length.
  - Ordering: placed before day exceptions.
  - Start day: candidates are synthetic days whose weekday equals the weekday of the first sequence date (pure date arithmetic) and where the trip fits. The start is drawn with `rngFor(seed, "trip", node)`.
  - Day fields: days get `day_type: "trip_day"`, template `trip_day`, and `trip: { node, index }`.
  - Exception record: `{ scope: "multi_day", type: "trip", replaces: [<base day types>], day_range: [s, e], node }`, repeated on each trip day.
  - Donor times: trip days use the weekend donor.
  - Overlap: no other exception lands on trip days.
- **N4. `trip_day` template:** slots in this order, per spec §3.3:
  1. lodging_morning — required, anchor wake
  2. breakfast — `$trip:meal`, optional, anchor breakfast
  3. outing — required, anchor sport
  4. lunch — `$trip:meal`, optional, anchor lunch
  5. outing_pm — optional
  6. dinner — `$trip:meal`, optional, anchor dinner
  7. lodging_evening — optional

  The templates file becomes `templates.v3.json`, version `templates.v3`. The other day types are unchanged.
- **N5. Matching and verifier:**
  - New hard filter `trip_sequence`: a slot with `trip: {node, index}` accepts only clips whose `day_group === binding.day_group_sequence[index]`. It is never relaxed.
  - New verifier rule `trip`: all clips of trip days come from that trip's virtual nodes and from the sequence date at their index, and no home or workplace clip appears on trip days.
- **N6. Missing-required allowance:**
  - Dial: `dials.missing_required_allowance: [{ role, max_days }]` (default []).
  - Behaviour: in `fillTimeline`, a required slot whose role is listed and that has no candidate at any ladder level is dropped with relaxation `dropped_required`, while fewer than `max_days` days have used it. This happens before day regeneration.
  - Recording: `realized.dropped_required` (by role).
  - Verifier: `slot_window` accepts such slots, and fails if the count exceeds `max_days`.
  - The user chose this fallback for at most one day.
- **N7. NextMe L3 labeler (ingest):**
  - CLI: `ingest nextme` gains:
    - `--source-dir <dir>`: reads `raw/recordings.csv` and `captions/1_nextme/...` from a local HF download;
    - `--clip-level L3|L4` (default L4, current behaviour);
    - `--overrides <json>`.
  - Clip rules: L3 clips are segments ≥ 120 s. Place comes from the L3 text, then the enclosing L4, then L5, using the extended rules in `config/nextme_label_rules.l3.json`. That file holds the places from the scratch labeler and `trip_dates` with lodging, outing and meal words.
  - Overrides: entries `{ day_group, from: "HH:MM", to: "HH:MM", node, setting, category }` relabel clips that start in that range and are still unlabeled.
  - Defaults: the current L4 path and its tests are unchanged.

## Review Focus
1. Existing worlds produce byte-identical schedules to HEAD.
2. Trip days use only sequence-ordered dates, and no home or work clip appears on them.
3. Exactly `late_workdays_per_week × weeks` late days, minus trip days.
4. `dropped_required` never exceeds `max_days`, and is recorded in realized and the manifest.
5. The NextMe 28-day run either succeeds or fails with a capacity report naming the node and numbers.
