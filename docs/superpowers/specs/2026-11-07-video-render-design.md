# Video Render — 설계 스펙

- 날짜: 2026-11-07
- 상태: 리뷰 대기
- 관련 스펙: `2026-11-02-video-composer-mcp-design.md`

## 1. 목적

manifest를 실제 영상으로 합성해, 샘플 5개를 사람이 직접 보고 판단할 수 있게 한다. 전체 파이프라인에서 이 스펙의 위치는 다음과 같다.

1. manifest 생성 (완료)
2. **manifest로 영상 합성 (이 스펙)**
3. 영상을 보고 샘플을 수정한 뒤 5개를 고정한다
4. 합성으로 생기는 QA를 자동으로 만들기 위한 QA 카테고리를 정한다
5. 샘플 QA를 생성하고 사람이 검증한다
6. 시나리오를 짜고 대량 생성한다

## 2. 요구사항

### 합의된 결정

1. 벤치마크 영상은 전 구간 **1 fps**다. NextMe-800이 약 1 fps라서, 이벤트만 30 fps로 두면 화면 변화로 삽입 구간이 드러난다.
2. 벤치마크 영상에는 **오디오가 없다**.
3. 벤치마크 영상에는 **글자를 넣지 않는다**.
4. 샘플마다 벤치마크 영상과 검토 영상을 함께 만든다.
5. 검토 영상은 base를 8배속, 이벤트를 정속으로 재생하고 합성 시각, 블록 이름, caption을 표시한다.
6. 프레임은 1024×1024로 맞춘다.
7. 입력은 manifest뿐이다. 샘플을 고치면 새 manifest로 다시 실행한다.

### 기존 스펙에서 바뀌는 것

기존 스펙의 요구사항 6(원본 영상을 내려받지 않는다)은 샘플에 쓰는 원본에 한해 바뀐다. 샘플 5개에 필요한 파일만 `data/media/`에 받는다. 데이터셋 전체는 받지 않는다.

### 범위 밖

- QA 생성과 QA 카테고리 (영상을 본 뒤 별도 스펙)
- 샘플 내용 수정
- 오디오
- MCP 도구, UI
- Ego4D (라이선스 대기)
- 대량 생성을 위한 병렬 처리

## 3. 구성

새 패키지 `@vb/render`를 추가한다. `@vb/core`의 `ManifestSchema`로 입력을 검증하고, `ffmpeg`와 `ffprobe`를 자식 프로세스로 실행한다. 새 npm 의존성은 추가하지 않는다.

| 파일 | 역할 |
|---|---|
| `plan.ts` | manifest에서 프레임 계획을 만드는 순수 함수 |
| `nextme.ts` | NextMe 프레임 이름 파싱, 가장 가까운 프레임 찾기, tar 추출 |
| `media.ts` | 블록의 원본 파일 경로 찾기, 빠진 원본 검사 |
| `subtitles.ts` | 검토 영상용 ASS 자막을 만드는 순수 함수 |
| `ffmpeg.ts` | `ffmpeg`, `ffprobe` 실행 래퍼 |
| `render.ts` | 전체 흐름 |
| `cli.ts` | `npm run render` 진입점 |

실행 방법:

```bash
npm run render -- --manifest data/exports/883d71cd-r3.manifest.json
npm run render -- --manifest <path> --only review
```

`--only`는 `benchmark` 또는 `review`다. 데이터 루트는 ingest와 같이 `--data`, `VIDEO_BENCH_DATA_DIR`, 기본값 `./data` 순서로 정한다.

## 4. 원본 배치

| 데이터셋 | 위치 | 찾는 방법 |
|---|---|---|
| NextMe-800 | `data/media/nextme/<media.tar>` | manifest의 `media.tar` 경로 그대로 |
| Ego-Exo4D | `data/media/egoexo/<media.path>` | manifest의 `media.path` 경로 그대로 |
| HD-EPIC | `data/media/hdepic/` 아래 | `<video_id>.mp4`를 재귀로 찾는다 |

HD-EPIC manifest에는 `media.path`가 없고 다운로더의 폴더 구조도 문서에 없어서, 파일 이름으로 찾는다. 같은 이름이 둘 이상이면 오류다.

## 5. 프레임 계획

합성 시각 `t`초마다 프레임 1장을 쓴다. 프레임 수는 `N = ceil(duration)`이고, `n = 0 … N-1`에 대해 `t = n`이다.

1. `composed_start ≤ t < composed_end`인 블록을 찾는다.
2. 원본 시각은 `src = src_start + (t - composed_start)`이다. 기존 재매핑 규칙과 같다.

### NextMe (base)

- tar에서 `picture/masked/`의 JPEG만 임시 폴더로 풀고, 1024×1024로 줄여 `data/media/nextme/frames/<video_id>/`에 캐시한다. 임시 폴더는 끝나면 지운다. 샘플 5개가 이 캐시를 함께 쓴다.
- 프레임 시각은 파일 이름의 촬영 시각에서 읽는다. tar 순서는 시간순이 아니고, 프레임 수(13,589)도 초 수와 정확히 맞지 않아서 번호를 시간으로 쓰지 않는다.
- `start_wallclock + src`에 가장 가까운 프레임을 쓴다. 차이가 같으면 번호가 작은 쪽을 쓴다.
- 차이가 2초를 넘으면 그 구간을 리포트의 `gaps`에 남긴다. 렌더링은 계속한다.

### 영상 (이벤트)

- 블록마다 `ffmpeg`를 한 번 실행한다. 블록 안의 첫 `t`에 해당하는 원본 시각으로 이동해 1초 간격으로 필요한 장수만큼 뽑는다.
- 뽑은 프레임은 렌더링 작업 폴더에 두고, 끝나면 지운다.
- 정사각형이 아닌 원본은 비율을 유지하고 검은 여백을 넣는다.
- 필요한 구간이 원본 길이를 넘으면 오류다.

### 회전

원본의 회전 방향은 데이터셋별 설정값(0, 90, 180, 270)으로 둔다. 기본값은 0이고, 원본을 받아 프레임을 확인한 뒤 값을 정한다.

## 6. 결과물

`data/renders/<composition_id>-r<revision>/` 아래에 쓴다. 임시 이름으로 만든 뒤 이름을 바꿔서, 중간에 실패해도 불완전한 파일이 남지 않게 한다.

| 파일 | 내용 |
|---|---|
| `benchmark.mp4` | H.264, 1024×1024, 1 fps, 프레임 `N`장, 오디오 없음 |
| `review.mp4` | H.264, 1024×1024, 8 fps, 자막을 영상에 입힘, 오디오 없음 |
| `review.ass` | 검토 영상의 자막 원본 |
| `render.json` | 리포트 |

`render.json`에는 manifest 경로, 프레임 수, 블록별 프레임 수, 원본 시각과의 최대 차이, `gaps`, 회전 설정이 들어간다.

## 7. 검토 영상

벤치마크 영상과 같은 프레임을 쓴다. 8 fps로 고정하고, base 프레임은 1장씩, 이벤트 프레임은 같은 프레임을 8번 넣는다. 그래서 base는 8배속, 이벤트는 정속이 된다. 합성 시각에서 검토 영상 시각으로 바꾸는 계산은 순수 함수로 둔다. 샘플 5개의 길이는 32~44분이다.

화면 위쪽에는 합성 시각, 역할과 카테고리, 블록 요약을 표시한다. 화면 아래쪽에는 caption을 표시한다.

| 구간 | 표시할 caption |
|---|---|
| base | `L2` |
| 이벤트 | `narration` 또는 `atomic`. 다음 caption까지, 최대 5초 표시 |
| 이벤트에 위 둘이 없을 때 | `keystep` |

caption 원문은 그대로 쓴다. ASS 특수 문자는 표시할 때만 이스케이프한다. 글꼴은 Noto Sans다.

## 8. 실패 처리

- `ffmpeg`나 `ffprobe`가 없으면 시작하지 않는다.
- 작업 전에 모든 블록의 원본을 검사하고, 빠진 파일을 한 번에 모두 보여 준 뒤 종료한다.
- 같은 revision을 다시 렌더링하면 덮어쓴다. 프레임 캐시는 다시 만들지 않는다.
- 프레임 이름을 해석할 수 없으면 그 파일 이름을 보여 주고 종료한다.
- `ffmpeg`가 실패하면 stderr 마지막 부분을 보여 주고 임시 파일을 지운다.

## 9. 검증

자동 테스트는 `ffmpeg`로 만든 합성 영상과 합성 manifest만 쓴다. 실제 데이터는 저장소에 넣지 않는다. `ffmpeg`가 없으면 테스트를 건너뛰지 않고 실패시킨다.

- 프레임 계획: 소수점 블록 경계, 마지막 프레임, 블록 사이 이동
- NextMe: 시간순이 아닌 입력, 동률, 2초 초과 구간
- 영상 추출: 프레임 색으로 시각을 인코딩한 합성 영상에서, 뽑힌 프레임이 맞는 시각인지 확인
- 결과물: 프레임 수, fps, 해상도, 오디오 스트림 없음을 `ffprobe`로 확인
- 검토 영상: 시각 변환, 자막 시각, caption 선택 규칙, 이스케이프
- 실패: 빠진 원본 목록, 원본 길이 초과

실제 샘플에서는 다음을 확인한다.

- 샘플 5개의 프레임 수가 `ceil(duration)`과 같다
- 블록 경계 앞뒤 프레임이 올바른 원본에서 나왔다
- `gaps`와 최대 차이를 사용자에게 보고한다

## 10. 데이터 취급

`data/media/`와 `data/renders/`는 라이선스 데이터의 파생물이다. `.gitignore`의 `data/`에 포함되며 커밋하거나 공개하지 않는다.

## 11. 구현 후 확인할 항목

1. 데이터셋별 회전 값
2. NextMe 프레임 이름의 시각과 caption 시각이 같은 시계인지
3. Lab22 CLI로 받은 파일 경로가 `media.path`와 맞는지 (`--uids`, `--views` 필터는 `--help`에서 확인함)
