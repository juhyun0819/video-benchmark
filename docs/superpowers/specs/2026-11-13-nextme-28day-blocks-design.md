# NextMe 28일: 실제 하루를 블록으로 채우기 (설계)

- 작성일: 2026-11-13
- 상태: 승인 (2026-11-13). 취미 슬롯은 빈칸으로 둔다.
- 관련: `2026-11-12-nextme-28day-design.md`(늦은 출근, 여행, 집(아침) 비우기), 계획 `2026-11-12-nextme-28day.md` Task 1~4(완료)

## 1. 왜 바꾸나

지금 방식은 슬롯마다 시간대가 맞는 클립을 찾아 끼운다. 그래서 하루 영상이 중앙값 2.0시간밖에 안 된다. 실제 NextMe 녹화는 하루 중앙값 7.5시간이다. 일할 때는 몇 시간 동안 계속 일하는 영상인데, 그것을 조각으로만 쓴다.

## 2. 유지하는 것

- 일정은 지금 생성기 그대로 만든다.
  - ATUS 실제 응답자(donor)의 하루로 기상, 출근, 식사, 퇴근, 취침 시각을 정한다.
  - 날 유형도 그대로다. 평일, 늦은 출근(주 2일), 쉬는 날(취미, 집), 연차 같은 예외, 여행이 있다.
  - 취미 슬롯 위치도 생성기가 정한다.
- manifest 스키마와 Task 1~4 코드는 그대로 둔다. 기존 world의 결과도 바뀌지 않는다.

## 3. 바뀌는 것

### 3.1 여행 요일

- `dials.trips[]`에 선택 필드 `start_day`(합성 날 번호)를 더한다.
- 지정하면 여행이 그날 시작한다. 요일 맞추기와 seed 추첨을 하지 않는다. 없으면 지금처럼 원본 여행 첫날의 요일을 따른다.
- 이번 world는 `start_day: 19`로 둔다. 3주차 금요일이고, 4주 world는 월요일에 시작한다. 원본은 6/29~7/1(월~수)이고, 합성에서는 D19~21(금~일)에 들어간다.

### 3.2 블록 채우기 (`npm run compose-blocks -- --world <path>`)

1. **실제 날짜 배정.** 합성 하루마다 실제 NextMe 날짜를 하나 쓴다(1:1).
   - 평일과 늦은 출근일에는 직장 영상이 있는 실제 날을 쓴다.
   - 쉬는 날에는 직장 영상이 없는 실제 날을 쓴다.
   - 여행일에는 6/29, 6/30, 7/1을 순서대로 쓴다.
   - 같은 유형 안에서는 집(아침) 영상이 있는 날, 그다음 실제 영상이 긴 날을 먼저 쓴다. 배정은 seed로 정해진다.
2. **실제 하루를 장소 구간으로 나눈다.** 클립 라벨(키워드, 수동 overrides, 같은 장소 사이 추정)로 집, 이동, 직장, 식사, 산책 구간을 만든다.
3. **블록을 채운다.** 일정의 각 블록 시작 시각부터 그 장소의 실제 영상을 실제 순서대로 이어 붙이고, 블록이 끝나면 자른다.
   - 집(아침): 그날 집을 나서기 전의 집 영상
   - 출근, 퇴근: 일정의 이동 시간에 그날 실제 이동 영상
   - 오전 근무: 실제 점심 전 직장 영상. 오후 근무: 실제 점심 후 직장 영상
   - 점심, 저녁: 그날 실제 식사 장면. 장소는 실제 장소다.
   - 집(저녁): 귀가 후 집 영상
4. **취미와 예외.** 일정에 들어간 취미 슬롯은 산책이 아닌 다른 취미로 채울 예정이다. 그래서 이번에는 빈칸(`unrecorded`)으로 둔다(사용자 결정, 2026-11-13). 연차 같은 예외 날은 일정 그대로 둔다.
5. **영상이 없는 블록**은 비우고 `unrecorded`로 남긴다.

### 3.3 manifest와 검사

- 클립마다 잘라 쓴 실제 구간(`source_start_s`, `source_end_s`)과 원래 실제 시각을 기록한다.
- verifier는 이 모드에서 `time_of_day` 규칙을 끈다. 실제 시각과 합성 시각이 다를 수 있기 때문이다.
- 나머지 규칙은 유지한다: 블록 창 안, 날짜 하나는 하루에만, 여행 날짜 순서, 여행일에 집·직장 클립 없음.
- 검수표에 날짜별 실제 날짜, 블록별 실제 시각 범위, 추정 라벨 여부, 하루 총 길이를 보여 준다.
