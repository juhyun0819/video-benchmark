# NextMe 28일 실제 프레임 렌더러 설계

- 날짜: 2026-11-13
- 상태: **승인됨(2026-11-14).** 검토에서 녹화 끝 규칙(§5 NextMe)을 더했다. 다음은 `superpowers:writing-plans`로 구현 계획을 쓴다.
- 대상: `data/exports/nextme-p00-e274ee8b-r0.manifest.json`(블록 방식 28일 manifest)
- 관련: `2026-11-13-nextme-frame-fetch-design.md`(NextMe 프레임 캐시), `2026-11-07-video-render-design.md`(옛 렌더 설계, 대체됨. 아래 "옛 설계와의 관계" 참고)

## 1. 목적

manifest를 실제 원본 프레임으로 하루 하나씩 벤치마크 영상으로 만든다. 프록시 영상(`scripts/render_proxy.py`)이 아니라 실제 NextMe, Ego4D, YouTube 화면이 들어간다.

## 2. 합의한 결정

| 항목 | 결정 |
|---|---|
| 결과물 | 벤치마크 영상만(검토 영상 없음). 하루에 하나 |
| 방법 | Python 스크립트 하나 `scripts/render_frames.py`(Pillow + ffmpeg). 프록시 렌더러, 프레임 fetcher와 같은 방식 |
| 영상 없는 구간 | 건너뛴다. 다음 클립이 바로 이어지고 타임스탬프 시각만 건너뛴다 |
| 타임스탬프 | 모든 프레임에 넣는다. 형식 `YYYY-MM-DD HH:MM:SS`, 시간대 없음, 숫자 높이 20px |
| 날짜 | 1일차 = 2025-04-07(월). 미래 연도는 VLM이 "아직 오지 않은 영상"으로 볼 수 있어서 과거 연도를 쓴다 |
| 정사각형 맞추기 | Ego4D·YouTube는 가운데를 정사각형으로 자른다 |
| 어안 모양 | Ego4D·YouTube에 NextMe와 같은 원 모양 가리기를 한다. 어안 휘기 강도는 설정값(기본 0)이고, Ego4D를 받은 뒤 비교 이미지로 정한다 |

CLAUDE.md의 "화면 글자가 없다"는 규칙에 예외가 하나 생긴다: **우리 타임스탬프 한 줄만은 넣는다.** 모델이 시각을 영상에서 읽어야 하기 때문이다.

## 3. 흐름 (하루마다)

1. **프레임 목록**: 그날 클립을 `synthetic_start_s` 순서로 놓고, 정수 합성 시각 `t`마다 1장을 정한다.
2. **원본 확인**: 그날 필요한 NextMe 프레임, Ego4D 영상, YouTube 영상이 다 있는지 본다. 모자라면 그날은 건너뛰고 무엇이 없는지 모아서 보여 준다. 다운로드 중에도 다 받은 날부터 만들 수 있다.
3. **프레임 준비**: NextMe는 캐시의 1024 프레임. Ego4D·YouTube는 가장 가까운 프레임을 뽑아 회전, 가운데 자르기, 1024 축소, 원 가리기.
4. **타임스탬프** 쓰기.
5. **인코딩**: 1 fps, 1024×1024, 오디오 없음.

## 4. 프레임 목록

- `synthetic_start_s`, `synthetic_end_s`는 28일 전체에 걸친 절대 초다. 그날의 기준은 `base = (day_index - 1) × 86400`이다.
- 클립마다 `synthetic_start_s ≤ t < synthetic_end_s`인 정수 `t`가 한 장씩이다. 경계가 소수라서 길이가 같아도 1장 차이가 날 수 있다(옛 설계 §5와 같다).
- 원본 시각은 `src = source_start_s + (t - synthetic_start_s)`다.
- 클립 사이(`no_video_spans` 포함)의 `t`는 프레임을 만들지 않는다. 영상의 다음 장은 다음 클립의 첫 장이다.
- 28일 합계 약 664,454장(184.6시간)이다. 계획 단계에서 이 수와 맞는지 확인한다.

## 5. 원본별 규칙

### NextMe (`source.dataset = nextme800`)

- 프레임 번호 `n`의 시각은 `start_wallclock + n초`다(fetch 설계 §3).
- `n = round(src)`(반올림, 0.5는 작은 쪽)의 프레임을 `data/media/nextme/frames/<video_id>/`에서 찾는다. 파일 이름 끝의 `__frame_NNNNN.jpg`로 번호를 읽는다.
- 없으면 `n ± 2` 안의 가장 가까운 프레임을 쓰고(같은 거리면 작은 번호) 리포트 `substitutions`에 남긴다. 2초 안에도 없으면 그날은 오류다.
- 녹화 끝: `n`이 그 영상의 마지막 프레임 번호보다 크면, 5초 이하로 넘을 때까지는 마지막 프레임을 반복하고 리포트 `clamped`에 남긴다. 5초를 넘으면 그날은 오류다. 마지막 프레임 번호는 fetcher index(`data/media/nextme/index/<video_id>.jsonl`, 끝까지 훑은 경우 `{"end": true}`가 있음)에서 읽는다. 끝까지 훑지 않은 영상이면 이 규칙을 쓰지 않고 위의 2초 규칙만 쓴다.
  - 검토 때 확인(2026-11-14): 18일차 `d18-s4`(`2026-07-23_1353-1637`, 원본 9698–9841초)는 녹화 끝(9836번)보다 4초 길고, 1일차 `2026-04-28_1204-1623`은 2초 길다. 다른 클립은 녹화 안에 있다. 다 받은 tar에 중간 구멍은 없다.
- 캐시 프레임은 이미 1024×1024이고 어안 원이 있다. 자르기와 원 가리기를 하지 않는다.

### Ego4D·YouTube (`media.kind = video`)

- 원본 경로: Ego4D `data/media/ego4d/v2/full_scale/<video_uid>.mp4`(lab22 다운로드 위치, 확인함), YouTube `data/media/youtube/<video_id>.mp4`.
- 시각 맞추기는 옛 설계 §5 "영상" 규칙을 그대로 쓴다.
  - 프레임 `k`의 원본 시각은 `pts_k − pts_0`이다. `pts_0`이 0이 아니면 리포트에 남긴다.
  - 가장 가까운 프레임을 쓴다. 같은 거리면 앞 프레임.
  - `src`가 마지막 프레임보다 늦어도 한 프레임 간격(`1 / fps`) 이하면 마지막 프레임을 쓰고 `clamped`에 남긴다. 그보다 크면 그날은 오류다.
  - 추출은 클립마다 ffmpeg 한 번(`-ss`, `-copyts`, `select`). `-ss`와 `fps=1` 조합은 쓰지 않는다.
- 모양 맞추기, 순서대로:
  1. 회전: ffmpeg가 회전 메타데이터를 적용한 뒤, 데이터셋별 설정값(0/90/180/270, 기본 0)만큼 더 돌린다.
  2. 가운데를 정사각형으로 자른다(Ego4D 1920×1440이면 1440×1440, YouTube 16:9도 같다).
  3. 1024×1024로 줄인다(LANCZOS).
  4. 어안 휘기(설정값 `warp`, 기본 0이면 하지 않음). 강도는 Ego4D 비교 이미지로 정한다.
  5. 원 가리기: 중심 (494, 507), 반지름 500px까지 그대로, 500→560px에서 검게 어두워진다. NextMe 프레임 300장 평균에서 잰 값이다.

## 6. 타임스탬프

- 원본 NextMe 글자는 1024 기준 x 10–189, y 1005–1014(약 10px, `2026-04-20 11:35:04 HKT`)에 있다.
- 먼저 검은 상자로 덮는다. 상자는 원본 글자 영역 `(0, 995, 200, 1024)`를 포함하고, 새 글자 상자보다 작지 않다. 원본 글자는 하나도 남지 않아야 한다.
- 새 글자: 흰색, DejaVu Sans Mono Bold, 숫자 높이 20px, x = 10, 아래 여백 10px, 상자 안쪽 여백 `max(3, 글자높이/3)`. 시험 이미지 `.superpowers/viz/stamp-sizes.png`의 20px 안이다.
- 내용: 날짜 = 2025-04-07 + (day_index − 1)일, 시각 = `t − base`. 86400 이상이면 날짜를 하루 넘긴다(지금 manifest에는 자정을 넘는 클립이 없다).
- 모든 데이터셋의 모든 프레임에 같은 위치, 같은 모양으로 넣는다. 글자가 없는 화면이 "끼워 넣은 영상"으로 드러나지 않게 하기 위해서다.
- 글꼴 파일이 없으면 시작하지 않는다.

## 8. 실행과 이어 하기

- `python3 scripts/render_frames.py <manifest> [--days 1|1-7,10] [--jobs N] [--warp 0] [--out …]`
- 하루가 한 작업 단위다. `--jobs`로 여러 날을 동시에 만든다. 인코딩이 가장 오래 걸린다.
- 임시 이름으로 다 쓴 뒤 이름을 바꾼다. 중간에 끊겨도 반쯤 만든 파일이 남지 않는다.
- 다시 실행하면 `D01.render.json`의 manifest 정보(경로, `id`, `revision`, `created_at`)와 설정(시작 날짜, 글자 크기, 원 값, `warp`, 인코딩)이 지금과 같은 날은 건너뛴다. 다르면 다시 만든다.

## 9. 오류 처리와 리포트

- 시작 전: ffmpeg와 libx264, 글꼴이 없으면 시작하지 않는다. 날마다 원본을 확인해 모자란 날을 건너뛰고 한 번에 정리해 보여 준다(예: "3일차: Ego4D `3efc152d…` 없음, NextMe 프레임 120장 없음").
- 도중: 한 날의 오류(NextMe 2초 넘게 빈 프레임, NextMe 녹화 끝 5초 넘게 지남, 영상 끝 1프레임 넘게 지남, ffmpeg 실패)는 그날만 멈춘다. ffmpeg 오류는 stderr 끝부분을 보여 주고 그날 임시 파일을 지운다. 다른 날은 계속한다.
- 종료 코드: 모든 대상 날이 성공이면 0, 건너뛰거나 실패한 날이 있으면 1.
- `D01.render.json`: 프레임 수, 클립별 프레임 수, `substitutions`(NextMe), `clamped`(NextMe 녹화 끝, 영상 끝), `pts_0`(영상), 회전(메타데이터, 설정), 원 값, `warp`, 타임스탬프 설정, 인코딩 설정, manifest 정보.

## 10. 테스트

자동 테스트는 합성 데이터만 쓴다(`scripts/test_render_frames.py`, pytest). 프레임마다 번호를 색으로 표시한 가짜 JPEG와 가짜 영상(ffmpeg로 생성)을 만든다.

- 프레임 목록: 1초 1장, 영상 없는 구간 건너뛰기, 소수 경계, 자정 넘김, 날짜 계산(1일차 = 2025-04-07)
- NextMe: 맞는 번호, 빠진 프레임 대체(2초 이내 성공, 초과 오류), 녹화 끝 반복(5초 이내 성공, 초과 오류, 끝까지 훑지 않은 영상에는 쓰지 않음)
- 영상: 30 fps 가짜 영상에서 정확한 프레임, 세로 영상 회전, 가운데 자르기, 끝 넘김(1프레임 이내 clamp, 초과 오류)
- 그림: 원 밖이 검은지, 타임스탬프 위치, 원본 글자 영역이 완전히 덮이는지
- 결과: 장 수, 1 fps, 1024×1024, 오디오 없음(ffprobe)
- 이어 하기(같은 설정이면 건너뜀, 바뀌면 다시 만듦)와 모자란 날 건너뛰기

실제 데이터 확인(사람이 본다, 테스트에 넣지 않음):

- 다 받은 하루(예: 1일차)를 먼저 만든다. 장 수가 계획과 같은지, 클립 경계 앞뒤가 맞는 원본인지, 타임스탬프가 읽히는지, 크기와 화질을 본다.
- Ego4D를 받으면 휘기 강도별 비교 이미지를 사용자에게 보여 주고 `warp`를 정한다.

## 11. 옛 설계와의 관계

`2026-11-07-video-render-design.md`에서 다음을 그대로 쓴다: 영상 시각 맞추기(`pts_0`, 가장 가까운 프레임, 1프레임 clamp, `select` 추출), 회전 규칙, 인코딩 표, 원자적 쓰기.

다음은 바꾼다:

- NextMe 캐시 `.complete`와 tar 풀기 → fetch 설계의 필요한 프레임만 받은 캐시
- NextMe 프레임 고르기: 파일 이름 촬영 시각 → 프레임 번호(`start_wallclock + n초`). 빈 프레임은 2초 안 대체, 녹화 끝은 5초까지 마지막 프레임 반복, 넘으면 오류(옛 설계는 `gaps`에 남기고 계속)
- 정사각형 아닌 원본: 검은 여백 → 가운데 자르기 + 원 가리기
- 결과물: `benchmark.mp4` + `review.mp4` 하나 → 하루마다 `Dnn.mp4`, 검토 영상 없음
- 화면 글자 없음 → 타임스탬프 한 줄
