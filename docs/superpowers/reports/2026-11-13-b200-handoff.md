# B200 서버로 옮기기: 다운로드와 렌더링 인수인계

날짜: 2026-11-13. 이 문서는 B200 서버에서 이어서 작업하는 Claude와 사용자를 위한 것이다.

## 왜 옮기나

convei-rack3의 인터넷 대역폭이 합계 약 12MB/s라서, NextMe 프레임(약 1.7TB를 받아야 함)과 Ego4D(약 120GB)를 받는 데 며칠이 걸린다. 대역폭이 병목이므로 B200에서 처음부터 새로 받고 렌더링까지 한다. convei-rack3에서 받은 것(NextMe 35,212장/591,047장, Ego4D 일부)은 옮기지 않는다.

## 지금 상태 (2026-11-13 기준)

- 브랜치 `feat/nextme-28day`. 목표는 NextMe 착용자 28일 manifest 하나를 실제 프레임 영상으로 만드는 것이다(CLAUDE.md "진행 중" 절).
- manifest: `data/exports/nextme-p00-e274ee8b-r0.manifest.json`(약 248MB, git에 없음). 클립 1,033개: nextme800 1,010, ego4d 20, youtube 3. 합계 664,454프레임(1 fps, 184.6시간).
- NextMe fetcher `scripts/fetch_nextme_frames.py`: 구현과 테스트 완료(19개 통과), 실제 데이터로 확인함. 설계 `docs/superpowers/specs/2026-11-13-nextme-frame-fetch-design.md`.
- 렌더러: 설계 대화를 마치고 스펙 초안 `docs/superpowers/specs/2026-11-13-nextme-frame-render-design.md`을 썼다. **사용자 검토 전이다.** 승인 → `superpowers:writing-plans`로 계획 → 실행 방식 선택 → 구현 순서다. 코드는 아직 없다.

## B200에서 할 일

### 1. 코드와 manifest

- 저장소를 clone하고 `feat/nextme-28day`를 checkout한다.
- manifest는 git에 없다. 둘 중 하나로 가져온다.
  - convei-rack3에서 사용자가 `python3 scripts/sync_data.py push`(비공개 HF 저장소 `zzu819/videomem`) → B200에서 `python3 scripts/sync_data.py pull`. `exports`, `catalog`, `renders`(프록시 116MB) 등이 함께 온다.
  - 또는 `scp`로 manifest 파일 하나만 복사한다. 다운로드와 렌더링에는 manifest만 있으면 된다.
- manifest를 다시 만들 필요는 없다. 다시 만들려면 `data/raw`, `data/catalog`가 필요하다(CLAUDE.md의 실행 명령).

### 2. 저장 위치

- 큰 파일은 B200의 로컬 디스크에 둔다. 필요한 공간: NextMe 1024 프레임 약 230GB, Ego4D 약 120GB, YouTube 수 GB, 렌더 결과(크기 미정, 첫날로 잰다). 여유를 두고 500GB 이상.
- convei-rack3처럼 `data/media`와 `data/renders`를 로컬 디스크 폴더(권한 700)로 가는 심볼릭 링크로 만든다. B200에서 저장소가 NAS에 있으면 이렇게 하고, 로컬이면 그냥 폴더로 둔다.
- 경로를 정하면 CLAUDE.md "서버 환경" 절과 메모리에 적는다.

### 3. 환경 확인

- Python 3.9 이상, `requests`, `Pillow`, `pytest`(fetcher와 테스트), `huggingface_hub`(sync_data.py)
- `ffmpeg`(libx264 포함), 글꼴 DejaVu Sans Mono Bold(렌더러 타임스탬프)
- Lab22: `uvx`(`pip install --user uv`), 키는 저장소 `.env`의 `LAB22_API_KEY`(git에 없음. 사용자가 직접 넣고 직접 실행한다)
- Node 24는 manifest를 다시 만들 때만 필요하다.
- 먼저 `python3 -m pytest scripts/test_fetch_nextme_frames.py -q`로 19개 통과를 확인한다.

### 4. NextMe 프레임 받기 (사용자가 자기 셸에서)

```bash
export HF_TOKEN=...   # 사용자가 직접. Claude는 값을 보거나 쓰지 않는다
python3 scripts/fetch_nextme_frames.py data/exports/nextme-p00-e274ee8b-r0.manifest.json --days 1 --jobs 12
python3 scripts/fetch_nextme_frames.py data/exports/nextme-p00-e274ee8b-r0.manifest.json --jobs 12 2>&1 | tee -a data/media/nextme/fetch_all.log
```

- 하루치로 먼저 속도를 잰다. convei-rack3에서는 `--jobs 12`가 6보다 빨랐다(11.4 vs 8–9MB/s, 서버 회선 한계). B200에서는 회선이 넓으면 `--jobs`를 더 올려 본다.
- 다시 실행하면 이어 받는다. 진행은 `data/media/nextme/fetch_status.json`, 1분마다 로그 한 줄.
- `missing 2`(`2026-07-27_0849-0942`의 3182–3183번)는 녹화 끝(마지막 3181번) 뒤의 여유 프레임이라 문제없다.
- `hf auth login`은 하지 않는다(공용 서버 규칙). 토큰은 환경 변수로만 쓴다.

### 5. Ego4D 영상 20개 받기 (사용자가 직접)

uid 목록은 manifest에서 만든다(convei-rack3의 `data/media/lists/ego4d_video_uids.txt`와 같은 20개임을 확인함).

```bash
mkdir -p data/media/lists && python3 -c "import json;m=json.load(open('data/exports/nextme-p00-e274ee8b-r0.manifest.json'));print('\n'.join(sorted({c['video_id'] for d in m['days'] for c in d['clips'] if c['source']['dataset']=='ego4d'})))" > data/media/lists/ego4d_video_uids.txt
```

```bash
lab22 ego4d --output_directory data/media/ego4d --datasets full_scale --video_uid_file data/media/lists/ego4d_video_uids.txt
```

- 파일은 `data/media/ego4d/v2/full_scale/<uid>.mp4`에 생긴다. 합계 64시간, 1920×1440 VP9, 약 120GB.
- 영상 전체를 받지만 manifest는 그중 약 14시간만 쓴다(블록 길이에 맞춰 잘라 씀). 기타 클립 4개(9·15·23·25일)는 서로 다른 영상이고, 원본 시작이 모두 0.021초인 건 `video_start_sec`이 그 값이라서다.

### 6. YouTube 영상 1개 (사용자가 직접)

- `MALryOlc3TU`를 `data/media/youtube/MALryOlc3TU.mp4`로 받는다. 오디오 필요 없음, 1080p 이하, 길이 6시간 49분 이상이어야 한다(6·13·27일에 0–7953, 7954–14284, 14285–24522초를 쓴다).

### 7. 렌더러

- 스펙 초안을 사용자에게 보여 주고 승인을 받는다. 그다음 writing-plans → 구현(superpowers 스킬, TDD, 합성 fixture만).
- Ego4D를 받으면 어안 휘기 강도별 비교 이미지를 만들어 사용자가 `warp`를 고르게 한다.
- 다 받은 날부터 하루씩 만든다. 1일차를 먼저 만들어 장 수, 클립 경계, 타임스탬프, 크기·화질을 확인한다.

## 지켜야 할 규칙 (CLAUDE.md에서)

- 토큰과 키 값은 출력하거나 기록하지 않는다. 있는지만 확인한다. HF_TOKEN은 사용자 셸의 환경 변수로만.
- Lab22 CLI는 사용자가 직접 실행한다.
- `data/`(배포 통계 제외)는 커밋하거나 공개하지 않는다. 공개 저장소에 올리지 않는다.
- 커밋과 push는 요청받았을 때만 한다. 테스트 fixture는 합성 데이터만.
- 코드, 메시지는 영어, 대화와 스펙은 한국어. 사용자에게는 쉬운 한국어로, 번호 붙인 선택지와 예시로 묻는다.
