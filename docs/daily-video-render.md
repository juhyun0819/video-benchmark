# 일별 영상 합성

`scripts/render_daily_videos.py`는 manifest에 배치한 **완성된 1fps 입력 파일**을 시간순으로 연결한다. 기본 출력은 **1024×1024, 무음, 1fps**다. 화면 비율을 유지해 축소·확대하고 남는 영역은 검은 여백으로 채운다. 기존 시각 표시 영역을 가린 뒤, 크기 조정이 끝난 화면에 합성 날짜·시각을 표시한다.

원본 전체를 선택한 슬롯은 원본 전체 입력을 사용한다. 캡션 검토로 승인한 구간은 앞 단계에서 만든 해당 구간 파일 전체를 사용한다. 이 도구는 시간표 길이에 맞춰 다시 자르거나 프레임을 추가·생략하지 않는다. 원본 파일과 승인 구간을 혼동해 입력하면 길이 검증에서 실패한다.

## 실행

저장소 루트에서 실행한다. 아래 경로는 공유 NAS의 예시이며 실제 프로젝트 경로로 바꾼다. Python 3.10 이상, FFmpeg·ffprobe, DejaVu Sans Mono Bold 폰트가 필요하다.

```bash
NAS_PROFILE=/mnt/nas/project/profile

python3 scripts/render_daily_videos.py \
  --manifest "$NAS_PROFILE/caption-pipeline/manifest.json" \
  --output "$NAS_PROFILE/daily-videos" \
  --base-date 2025-07-07 \
  --timezone Asia/Seoul \
  --workers 2 \
  --threads 2
```

`--workers`는 동시 처리 클립 수, `--threads`는 각 인코딩 작업의 스레드 설정이다. `--day 1`을 추가하면 Day1만 처리한다. `--day`는 여러 번 지정할 수 있다. 생략하면 manifest에 선택된 모든 날짜를 처리한다.

파일 경로만 보완할 때는 `--source-overrides /path/to/resolved-inputs.json`을 사용한다. JSON은 `{"d24-s6": "/mnt/nas/project/input.mp4"}`와 같은 슬롯 ID→파일 경로 객체다. 원본 ID와 선택 구간은 유지해야 한다.

`--wait-inputs`는 아직 없는 입력 파일이 최종 이름으로 나타날 때까지 기다린다. `--poll-seconds` 기본값은 30초다. manifest와 경로 보완 파일은 실행 시작 때 읽으므로, 배치나 경로 자체가 바뀌면 다시 실행한다. 다른 계획을 기존 출력 폴더에 섞지 않도록 새 출력 폴더를 사용한다.

## 출력

```text
daily-videos/
├── plan.json
├── input-manifest.json
├── status.json
├── coordinator.lock
├── segments/                  # 크기 조정·시각 표시를 마친 클립과 검증 정보
├── day01/
│   ├── video.mp4
│   ├── mapping.json
│   ├── captions.json
│   └── validation.json
└── day28/                     # 같은 구조
```

`mapping.json`은 최종 영상의 재생 구간·프레임 범위, 합성 시각, 원본 ID와 원본 구간을 연결한다. 재생 구간은 **입력 파일의 실측 길이 누적합**이다. 오전 영상 뒤에 오후 영상을 배치했다면 관측하지 않은 몇 시간은 영상에 넣지 않고 화면 시계가 다음 일정 시각으로 이동한다.

`captions.json`에는 캡션 원문과 원본 시각, 구간 내부 시각, 최종 영상 시각, 합성 날짜·시각을 함께 저장한다. 원본 구간 시작 오프셋은 한 번만 뺀다. 시간 정렬된 캡션이 없는 영상은 미정렬 정보로 남기며, 슬롯 이름에서 캡션을 생성하지 않는다. 캡션 문장은 화면에 자막으로 표시하지 않는다.

날짜는 슬롯의 `day` 필드와 `--base-date`로 계산한다. 예를 들어 Day13으로 옮긴 `d3-s7`도 Day13 영상에 들어간다. 시작 날짜가 2025-07-07이면 Day28은 2025-08-03이다.

`status.json`에서 완료 날짜와 입력 대기·실패 상태를 확인한다. 종료 코드는 완료 `0`, 오류 `1`, 입력 대기 `3`이다. 같은 출력 폴더에는 한 coordinator만 실행할 수 있으며, 그 안에서 클립을 병렬 처리한다. 재실행 시 유효한 처리 결과를 재사용한다.

1fps의 마지막 프레임 반올림 때문에 입력 파일 길이가 원래 선택 구간보다 1초 이내로 차이 날 수 있다. 최종 매핑에는 선택 구간과 실측 재생시간을 구분해 기록한다. 검증 결과는 프레임·길이·형식에 대한 것이며, 영상 내용·같은 집·같은 사람·낮밤의 시각적 일치까지 보증하지 않는다.

## 완성 영상 추가 검증

`validate_daily_videos.py`는 결과를 변경하지 않고 최종 영상과 매핑을 검증한다. `plan.json`, 날짜별 결과 파일, `segments/`의 정규화 영상과 JSON 검증 기록이 필요하다. 아래 명령에서 지정한 `--report` 파일만 새로 쓴다. 보고서 옵션을 생략하면 JSON을 표준 출력으로 출력한다.

```bash
python3 scripts/validate_daily_videos.py \
  --root "$NAS_PROFILE/daily-videos" \
  --workers 4 \
  --report "$NAS_PROFILE/daily-videos/deep-validation.json"
```

`--day 1`을 추가하면 Day1만 검사한다. `--day`는 반복해서 지정할 수 있고, 생략하면 계획에 있는 모든 날짜를 검사한다. 동시 검사 수는 최대 4개이며 각 프레임 검사에는 디코더 스레드 1개를 사용한다. 모든 영상 패킷을 읽으므로, 인코딩이 끝난 뒤 실행하면 NAS 읽기와 쓰기 경합을 줄일 수 있다.

검사 항목:

- 최종 영상의 1024×1024·1fps·무음 형식, 프레임 수, 실측 길이와 클립 합계.
- 모든 영상 패킷의 표시 시각이 `0, 1, …, N-1초`인지와 각 패킷 길이가 1초인지.
- **각 클립의 첫 프레임과 마지막 프레임**을 최종 영상과 정규화 클립에서 직접 디코딩하여 RGB 픽셀 SHA-256이 같은지. 압축 패킷을 잘라 비교하지 않는다.
- 원본 ID·선택 구간·슬롯 순서·합성 날짜·시각·정규화 기록의 해시와 파일 정보. 합성 시각이 겹치거나 다른 날짜로 넘어가는지도 검사한다.
- 캡션의 원본 시각→클립 내부 시각→최종 영상 시각→합성 시각 대응, 실제 재생 구간 경계, 미정렬 캡션의 명시 여부.

종료 코드는 검사 통과 `0`, 오류 `1`, 아직 완성되지 않은 날짜가 있음 `3`이다. 미완성 날짜는 `pending`으로 남긴다. 시간 정렬된 캡션이 없는 클립을 올바르게 표시했다면 영상 검사는 통과할 수 있지만, 상태는 `passed_with_caption_gaps`, `all_requested_segments_have_aligned_captions`는 `false`로 기록한다. 이는 캡션이 전 구간에 있다는 뜻이 아니다.

이 검사는 모든 패킷의 시간 정보를 확인하지만 **모든 프레임을 디코딩하거나 화면 내용을 검수하지는 않는다**. 같은 집·같은 사람·활동 내용·낮밤의 일치 여부는 별도 시각 검수가 필요하다.
